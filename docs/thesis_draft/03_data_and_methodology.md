## 3.1 Overview of the experimental design

The experiments in this thesis are organised into four stages that
depend on each other in strict order. Each stage produces artefacts
that feed the next, so a bug at any earlier stage would silently
poison every later number. The stages are:

1. **Data preparation.** Two speech corpora are prepared: DECTE
   (Diachronic Electronic Corpus of Tyneside English) as the dialectal
   test material, and VCTK 0.92 (loose English-accent subset) as a
   standard-accent control set. For each corpus a metadata bridge is
   built that maps audio files to per-speaker attributes (gender,
   age band, recording era, accent, region).
2. **Spoof generation.** For each speaker in each corpus, a fixed
   number of "target" utterances is synthesised by two zero-shot
   voice-cloning generators (XTTS v2 and OpenVoice v2), using
   reference audio drawn from the same speaker's remaining utterances.
   All generated files are logged in a merge-safe JSON-Lines manifest
   that records the original audio path, the generator, the reference
   audio, and the input transcript for each spoof.
3. **Detector evaluation.** Two detectors are evaluated on the
   generated spoofs against matched bonafide originals. The primary
   detector is the AuralGuard-AASISTPP wrapper around the AASIST
   backbone \cite{Jung2022_AASIST}; the second detector is a classical
   LFCC + Logistic Regression pipeline built specifically for
   cross-architecture replication. Both detectors share the same
   audio preprocessing and the same score-direction convention.
4. **Statistical analysis and mitigation.** Point-estimate metrics
   (EER, AUC, accuracy, FAR, FRR) are computed per subgroup and per
   corpus/generator combination. Non-parametric bootstrap resampling
   produces 95 % confidence intervals for every headline number and
   for the differences between them. Finally, a conservative partial-
   backbone fine-tune of the primary detector is trained on a
   leakage-safe DECTE speaker split and evaluated against the same
   held-out test slice, with a paired-bootstrap comparison against
   the baseline.

The whole pipeline is deterministic given a fixed random seed
(`seed = 42`, used consistently across speaker selection, target-
utterance sampling, bootstrap resampling, and the mitigation
Logistic-Regression fit).

An important design principle throughout is **matched-N per cell**.
Every cross-corpus or cross-generator comparison is reported with the
same number of spoof samples per side (typically 100), and every
before/after mitigation comparison uses the exact same files under
both detector configurations. This is what makes the bootstrap
confidence intervals interpretable as detector-effect intervals
rather than sampling-noise intervals.

## 3.2 Corpora

### 3.2.1 DECTE — Diachronic Electronic Corpus of Tyneside English

DECTE is a research-restricted corpus of interview-style speech from
speakers in the Tyneside region of North-East England
\cite{Corrigan_DECTE}. It spans three recording eras (1960s–1970s reel-to-reel
material, a 1990s follow-up survey, and a 2007–2011 modern digital
survey), and the interview genre keeps the acoustic and pragmatic
style of the recordings quite different from studio-read speech.

The corpus was pre-segmented into interview-level audio chunks by a
previous ASR/FairFix workflow before this thesis began. Those chunks
are stored under `data/01_chunks/` and total 10,066 files across 99
distinct interview audio streams (roughly one file per interview
after segmentation). Per-chunk transcripts produced by Whisper (with
FairFix normalisation) are stored under `data/01_chunk_transcripts/`.

**Speaker metadata.** The original TEI-XML transcripts (under
`data/decte/transcripts/Original/`) contain speaker-level
information — gender, age band, education, occupation, residence, and
recording era — inside `<SPEAKER DETAILS>` blocks. These were
extracted by `scripts/01_extract_decte_speaker_metadata.py` into a
per-speaker JSON file (`data/decte/metadata/speaker_info.json`, 200
speakers). Because DECTE audio filenames encode the *interview* (e.g.
`decten1pvc03audio_chunk_00043.wav`) rather than the individual
speaker within an interview, a bridge file was later generated by
`scripts/01b_bridge_metadata_by_audio.py` that maps each audio-stem
identifier (e.g. `decten1pvc03`) to collapsed interview-level
metadata (`data/decte/metadata/speaker_info_by_audio.json`). Where
speakers within an interview disagreed on a field, the field was
collapsed to `"mixed"`; where the field was missing, `"unknown"`.
This bridge is the file that all downstream DECTE processing uses.

**Duration and transcript filter.** Only chunks between 2 s and 15 s
in duration, and with a non-empty transcript of at least five
characters, were kept as candidate utterances. This filter produced
744 valid utterances across 96 speakers (Entry 5-adjacent, verified
by the `DECTELoader.build_utterance_list` call in
`src/data/decte_loader.py`).

**Known limitations of the DECTE data used here.** The transcripts
were produced by Whisper with FairFix and are known to lightly
normalise dialectal forms — some Tyneside-specific spellings or
grammatical cues may be lost. Whether this affects generator output
is not directly measured in this thesis, but it is flagged as a
transcript-pipeline confound in the Limitations chapter. Additionally,
the `speaker_ses_class` field is essentially unpopulated for DECTE
(the metadata extractor emits `education`, `occupation`, and
`residence` instead of a single SES class), so no per-SES analysis
is performed.

### 3.2.2 VCTK 0.92 — English standard-accent control

VCTK 0.92 is a widely used studio-recorded multi-speaker English
corpus containing approximately 110 speakers reading a common
sentence set at 48 kHz \cite{Veaux2017_VCTK}. It was chosen as the
standard-accent control because (a) it is not part of the primary
detector's training set (see Section 3.4), (b) it has per-speaker
accent metadata that allows an English-accent-only filter to be
applied, and (c) each speaker has hundreds of utterances, making
speaker-level sampling straightforward.

**Speaker filter and slate selection.** A layout-verification script
(`scripts/00b_verify_vctk_layout.py`) first confirms that the
expected VCTK 0.92 directory tree exists on disk and parses
`speaker-info.txt` into per-speaker attributes. For the experiments
in this thesis, the accent filter is *loose English*: any speaker
whose `ACCENTS` field equals `"English"` in the VCTK speaker-info
file, regardless of region. This produced 33 eligible speakers, of
which the alphabetically first 20 (with at least 8 usable utterances
each) form the VCTK slate for spoof generation. The region
composition of these 20 speakers is 13 southern (Southern England,
London, Surrey, SE England, SW England) and 7 non-southern
(Manchester, Cumbria, Stockton-on-Tees, Birmingham, Nottingham,
Staffordshire). No speaker is from Newcastle, so there is no
direct region overlap with DECTE.

**Duration and transcript filter.** VCTK's own `.txt` transcripts are
used (no Whisper is needed). The same 2 s–15 s duration filter as
DECTE is applied so both corpora feed the generators with comparable
utterance lengths.

**Known limitations of the VCTK data used here.** The 20-speaker
slate is heavily skewed toward the 21–30 age band (19 of 20; one
speaker in 31–40). DECTE, by contrast, spans several decades. Any
DECTE-vs-VCTK comparison in this thesis therefore has an age-band
confound alongside the dialect and channel confounds and is reported
as a *dialect / domain gap* rather than a pure dialect gap.

## 3.3 Spoof generators

Two spoof generators are used. They were chosen to represent two
different families of modern zero-shot voice cloning: an end-to-end
generative TTS model (XTTS v2) and a two-stage base-TTS-plus-tone-
colour-conversion pipeline (OpenVoice v2). Both are open-source and
publicly available.

Because the two generators have incompatible Python dependency
graphs — in particular, XTTS's Coqui TTS pins clash with OpenVoice's
MeloTTS pins, and OpenVoice's `openvoice.se_extractor` triggers a
broken PyAV DLL on Windows — each generator lives in its own
Conda environment (`spoofgen` for XTTS, `openvoice` for OpenVoice).
The detector evaluation pipeline runs in a third environment
(`dialectbias`) that has no generator dependencies. This
three-environment separation is deliberate and prevents dependency
regressions in one generator from silently breaking another.

### 3.3.1 XTTS v2 (Coqui)

XTTS v2 is a zero-shot voice-cloning multilingual TTS model that
takes a reference audio clip and a target text and produces speech
in the reference speaker's voice \cite{Casanova2024_XTTS}. The
implementation used here is `tts_models/multilingual/multi-dataset/
xtts_v2` from the Coqui `TTS` library, wrapped in
`src/spoof_gen/xtts_gen.py`. For each generation:

1. A single reference audio clip is prepared from the speaker's
   reference utterances (concatenated up to 10 seconds if more than
   one reference is supplied).
2. `TTS.tts_to_file(text, speaker_wav, language, file_path)` is
   called with `language="en"`, producing the spoof `.wav`.
3. If the output sample rate is not 16 kHz, the file is resampled to
   16 kHz so that downstream detectors see consistent input.

### 3.3.2 OpenVoice v2 (MyShell)

OpenVoice v2 uses a two-stage architecture \cite{Qin2023_OpenVoice}:
MeloTTS synthesises text in a fixed base voice, and a Tone-Colour
Converter then retargets the tone colour of the base audio to match
a target speaker's reference audio. The implementation used here is
wrapped in `src/spoof_gen/openvoice_gen.py`. For each generation:

1. MeloTTS produces a base-voice `.wav` from the input text, using
   `language="EN"` and `speaker_key="EN-US"`.
2. The Tone-Colour Converter loads its checkpoint (`converter/
   checkpoint.pth`) and a source speaker embedding
   (`base_speakers/ses/en-us.pth`) that matches the base-voice
   speaker.
3. The target speaker embedding is extracted from the reference
   audio using `converter.extract_se([ref_wav], se_save_path=None)`.
   The higher-level helper `openvoice.se_extractor.get_se` is
   deliberately bypassed because on the Windows evaluation machine
   its import chain triggered a broken PyAV DLL. The reference audio
   is already clean speech at 16 kHz and does not require the
   whisper-based VAD segmentation that `get_se` would provide, so
   the direct `extract_se` call is a safe substitute.
4. `converter.convert(...)` writes the final spoof `.wav`, which is
   then resampled to 16 kHz if needed.

### 3.3.3 Generation protocol

Both generators are driven by the same `SpoofPipeline` class in
`src/spoof_gen/pipeline.py`, so the *protocol* is identical between
them even though the underlying models are very different. For each
speaker:

- The `n_reference = 3` alphabetically first valid utterances are
  used as reference audio (voice identity).
- Up to `max_utterances_per_speaker = 5` remaining utterances are
  randomly sampled (using `random.seed(42)` at the top of the run)
  as target utterances; their audio path becomes the *matched
  original* for the eventual spoof, and their transcript becomes the
  spoof's input text.
- Each target utterance is synthesised by each enabled generator; the
  output `.wav` is written under `data/generated_spoofs/<generator>/`
  for DECTE and `data/generated_spoofs_vctk/<generator>/` for VCTK.
- Each generation appends a row to the corresponding manifest
  (`manifest.jsonl`), recording `source_utterance_id`,
  `source_speaker_id`, `generator_name`, `output_path`,
  `reference_audio_paths`, `input_transcript`, `source_audio_path`
  (the matched original), `corpus`, and success / error flags.

The manifest writer is *merge-safe*: on re-runs it loads any
existing manifest, deduplicates by `output_path`, and appends only
new rows. This lets the same manifest hold multiple generators and
lets partial runs be resumed without data loss (this behaviour was
added as a bug fix during development after an early run silently
truncated the XTTS half of the DECTE manifest).

### 3.3.4 Scale

Three generation scales are used across the thesis (small and
medium scales are validation-only and could be moved to an appendix
in the final version):

| Scale | Speakers | Utts/speaker | Purpose |
|---|---:|---:|---|
| Small test | 2 | 5 | End-to-end pipeline smoke test |
| Medium test | 7 | 5 | Confirm scaling before large run |
| Large / production | 20 | 5 | The 100-per-generator counts used in the thesis' headline tables |

Only the large-scale outputs feed the headline analyses in
Chapters 5–7. The specific YAML configs driving each scale live
under `configs/` (see Appendix A for the full config-to-scale index).

## 3.4 Detectors

Two detectors are used. The primary detector is a deep graph-attention
model (AuralGuard-AASISTPP); the secondary detector is a hand-crafted
LFCC + Logistic Regression baseline used specifically to test whether
the main findings persist across architectures.

Both detectors share the **same audio preprocessing** at score time:

- Read the file with `soundfile.read(..., dtype="float32",
  always_2d=True)`.
- Average across channels to mono if necessary.
- Resample to 16 kHz using `torchaudio.functional.resample` (AASIST)
  or `librosa.resample` (LFCC + LR).
- Deterministically zero-pad or truncate the waveform to exactly
  4.0 seconds (64,000 samples), starting from position 0 (no random
  crop at evaluation time).

Both detectors also share the **same score-direction convention**:
the returned score is `P(bonafide)` — higher score means "more
likely real". This is the convention required by
`src/evaluation/metrics.compute_metrics`. Getting the score direction
wrong (which would flip AUC below 0.5) is an easy silent bug and was
one of the diagnostic checks in Entry 3.

### 3.4.1 Primary detector — AuralGuard-AASISTPP wrapper around AASIST

The primary detector is the AuralGuard-AASISTPP wrapper (defined in
`auralguard-aasistpp/src/model_aasistpp.py` in the neighbouring
AuralGuard project) around the official AASIST backbone from
`clovaai/aasist` \cite{Jung2022_AASIST}. The AASIST backbone is a deep
graph-attention model over spectral–temporal representations of the
raw waveform; the AuralGuard wrapper adds three linear task heads on
top of AASIST's hidden features:

- `binary_head` — 2 classes (real / fake). This is the head used for
  scoring in this thesis.
- `attack_head` — 4 classes (bonafide, tts_vc, codec, partial).
  Trainable during fine-tuning but not read at score time.
- `explanation_head` — 4 classes (categorical explanation labels).
  Same as `attack_head`: trainable but not read at score time.

The trained checkpoint used as *baseline* throughout the thesis is
`auralguard-aasistpp/results/final_accent_globe_wavefake_balanced_full/
best.pt`, which was fine-tuned on a mixture of ASVspoof2019_LA,
WaveFake, GLOBE, EdAcc, EnglishDialects, and DECTE (17,603 bonafide +
17,603 spoof = 35,206 rows in the training CSV). The training-time
validation EER recorded in that checkpoint is reported in Chapter 4,
where the in-domain sanity check confirms that the loaded model
reproduces it.

**Validation.** During validation, the AASIST checkpoint-loading
path was corrected so that the trained AuralGuard wrapper, rather
than an untrained raw backbone, was evaluated. This correction was
verified using an in-domain sanity check before the DECTE and VCTK
experiments were interpreted. Chapter 4 documents the correction in
full; details are deferred here to keep this chapter methodology-
focused.

**Score computation.**

```
score = softmax(model(wav)["binary_logits"])[0, 0]
```

### 3.4.2 Secondary detector — LFCC + Logistic Regression

The secondary detector is a classical anti-spoofing baseline built
in `scripts/11_lfcc_lr_second_detector.py`. It is deliberately far
away from AASIST architecturally: hand-crafted spectral features,
a convex linear classifier, closed-form-ish optimisation.

**Feature extraction.** For each waveform (preprocessed as in the
introduction to Section 3.4):

1. Short-time Fourier transform with `n_fft = 512`, `hop_length =
   160`, `win_length = 400`, Hann window.
2. Take the magnitude-squared to get power.
3. Apply a linear-frequency triangular filter bank with 20 filters
   spanning 0–8 kHz (LFCC front-end — linearly spaced in Hz, unlike
   the perceptually spaced Mel front-end).
4. Log-compress the filter energies.
5. Apply a type-2 orthonormal DCT and keep the first 20 cepstral
   coefficients per frame.
6. Compute Δ and Δ-Δ features (first and second temporal derivatives)
   using `librosa.feature.delta`, concatenating the three streams to
   a 60-dimensional per-frame representation.
7. Pool over time by concatenating the per-dimension mean and
   standard deviation, yielding a fixed 120-dimensional vector per
   utterance.

**Classifier.** The classifier is a `sklearn.pipeline.Pipeline`
consisting of a `StandardScaler` followed by a `LogisticRegression`
with `class_weight="balanced"`, `C=1.0`, `max_iter=1000`,
`solver="lbfgs"`, and `random_state=42`. The scaler and classifier
are fit jointly on the training set and saved as a single
`joblib`-serialised object.

**Training data for the LFCC + LR classifier.** The classifier is
trained on the same AuralGuard training CSV that the primary AASIST
detector was originally fine-tuned on, *minus* the 16 DECTE speakers
held out for the mitigation test slice (Section 3.7). Filtering
those speakers out is essential — otherwise the LFCC + LR baseline
would be evaluated on speakers it had seen at training time,
biasing its DECTE performance upward. The filter removed 1,445 rows
from the 35,206-row training CSV (about 4 %), of which 8,057 → 6,612
were DECTE rows.

Path resolution for training-time audio: the AuralGuard training CSV
uses relative paths (e.g. `data\edacc_audio\val\...`) that resolve
against the AuralGuard project root, not the dialect-deepfake-bias
repository root. The training script resolves these correctly and
performs an existence pre-check on every path; only 80 files
(0.24 %) were missing on disk, well below the 5 % abort threshold.

**Score computation.**

```
bonafide_col = model.classes_.index(0)              # class 0 = bonafide
score = model.predict_proba(features)[0, bonafide_col]
```

### 3.4.3 Why these two detectors together

The two detectors differ on almost every axis that could matter:

| Aspect | AuralGuard-AASISTPP | LFCC + LR |
|---|---|---|
| Feature representation | Learned (raw waveform → SincConv → encoder) | Hand-crafted (STFT → linear filter bank → DCT) |
| Model family | Deep graph-attention | Convex linear |
| Number of parameters | ~300 k | ~121 (features + intercept) |
| Training objective | Cross-entropy over 3 heads (multitask) | Cross-entropy binary |
| Regularisation | Dropout + weight decay | L2 (via LR's default C) |
| Optimisation | AdamW SGD | LBFGS convex |

A finding that holds on *both* detectors is much less likely to be
an architecture-specific artefact than a finding that appears on only
one. This is why cross-detector replication (Chapter 5, Section 5.5)
is a central part of the thesis argument.

## 3.5 Evaluation protocol

The evaluation flow is implemented in `scripts/03_run_detectors.py`
and shared by both detectors. It takes three pieces of information
per run:

- a **detector config** (which detector to use and where its
  checkpoint lives) — one of `configs/detectors.yaml`,
  `configs/detectors_mitigated.yaml`, or
  `configs/detectors_mitigated_v2.yaml`;
- a **manifest** to evaluate (which spoofs to score and which
  bonafide files to pair them with);
- a **corpus label** used for grouping in downstream analysis
  (e.g. `decte`, `vctk_english_control`).

For each row of the manifest that has `success == True`, the script
constructs two evaluation records:

1. A **spoof record**: `audio_path = entry["output_path"]`,
   `label = 0`, `generator_name = entry["generator_name"]`.
2. One or more **bonafide records**. If the manifest row contains a
   `source_audio_path` field pointing to an existing file (as all
   post-Entry-5 rows and backfilled older rows do), that single path
   is used as the matched original (label=1). Otherwise, the fallback
   is every path in `reference_audio_paths` (label=1, one record
   per reference). The bonafide record's `generator_name` is set to
   the neutral string `"bonafide"`, so that later per-generator
   grouping does not incorrectly attribute a shared bonafide file
   to whichever generator happened to reference it first.

All records receive attached speaker metadata — gender, age band,
recording era — via a look-up into the per-speaker metadata JSON
(with the file-level collapse rule described in Section 3.2.1).
After deduplication on `(audio_path, label)`, the resulting DataFrame
is scored by the detector one row at a time; each row's `score`
column becomes the detector's `P(bonafide)` output.

**Per-corpus and per-group metric computation.** Metrics are computed
by `src/evaluation/metrics.py::compute_metrics(bonafide_scores,
spoof_scores)`:

- EER (equal error rate), obtained by finding the operating point at
  which `FPR ≈ FNR` on the ROC curve;
- AUC via `sklearn.metrics.roc_auc_score` \cite{Fawcett2006_ROC};
- Accuracy, false accept rate (FAR), and false reject rate (FRR) at
  the EER-threshold operating point.

Grouped metrics (per generator, per gender, per age band, per
recording era) are produced by `src/evaluation/bias_analysis.py`.
For generator groupings specifically, bonafide rows are pooled once
across the whole DataFrame and compared against each generator's
spoof rows separately, so that a shared bonafide file is not double-
counted or arbitrarily assigned to one generator.

## 3.6 Bootstrap confidence intervals

Point estimates alone are not enough for the sample sizes in this
thesis (typically 100 spoofs per corpus × generator cell against a
bonafide pool of 120–216). Every headline number in Chapters 5–7 is
reported with a 95 % non-parametric bootstrap confidence interval
\cite{Efron1993_Bootstrap}.

### 3.6.1 Fixed bootstrap parameters

- **Iterations:** `n_iters = 1000`.
- **Base random seed:** `seed = 42` (or `seed + 1` for the second
  arm of a paired comparison to avoid identical index sequences).
- **Resampling method:** independent, with replacement, at the
  original array size (`rng.choice(arr, size=len(arr), replace=True)`).
- **Confidence level:** 95 %, computed as the 2.5th and 97.5th
  percentiles of the bootstrap distribution of the statistic.
- **Statistic per iteration:** the EER (or delta EER for
  comparisons), computed on the resampled arrays using the same
  `compute_eer` function used for the point estimate.

These parameters are held fixed across all bootstrap scripts
(`scripts/04`, `scripts/05`, `scripts/06`, `scripts/10`, `scripts/12`,
`scripts/13`), so any two intervals in this thesis are directly
comparable in terms of estimator behaviour.

### 3.6.2 Two bootstrap flavours used

Two flavours of bootstrap appear in this thesis, distinguished by
what the two arms of a comparison have in common.

**Corpus comparisons — independent resampling per corpus.** For a
DECTE-vs-VCTK comparison holding the detector and generator fixed
(Chapter 5), the two corpora share no speakers and no files, so
the two sides can be resampled independently. On each of the 1000
bootstrap iterations, all four arrays (DECTE bonafide, DECTE spoof,
VCTK bonafide, VCTK spoof) are drawn with replacement at their
original sizes, the per-corpus EER is recomputed, and the difference
(DECTE − VCTK) is recorded. The percentiles of the 1000 recorded
differences give the 95 % confidence interval on the corpus gap
directly. Reading the CI on the gap this way (rather than combining
the two per-corpus CIs) is what lets a small consistent per-
iteration difference show a tight one-sided CI even when the two
per-corpus CIs overlap.

**Mitigation comparisons — paired comparison on the same files.**
For a baseline-vs-mitigated comparison of two detector checkpoints
(Chapter 6), both checkpoints are evaluated on the *same* held-out
files. Each file has a paired `(score_baseline, score_mitigated)`.
On each bootstrap iteration, the same set of file indices is drawn
for both checkpoints — the bootstrap sample is the same subset of
files under both models. The resulting delta EER is therefore a
within-file paired quantity, and its confidence interval isolates
the effect of the fine-tune from the noise of which files happen
to be drawn.

### 3.6.3 Verdict logic

For a gap CI on `A − B`, one of three verdicts holds:

- **Positive**: the entire CI is above zero → `A > B` at 95 %.
- **Negative**: the entire CI is below zero → `A < B` at 95 %.
- **Not distinguishable**: the CI includes zero → the sign of the
  difference is not statistically supported at 95 %.

All three verdicts appear in this thesis. Which comparison produces
which verdict is reported in Chapter 5 (corpus and generator
comparisons) and Chapter 6 (mitigation comparisons).

## 3.7 Mitigation protocol

The mitigation experiment (Chapter 6, Entry 7) fine-tunes the
AuralGuard-AASISTPP detector on a small DECTE-adapted training set
and evaluates the resulting checkpoint against the same held-out
DECTE test slice used by the baseline.

### 3.7.1 Speaker split

The 82 speakers who have both valid DECTE bonafide utterances *and*
at least one successful XTTS spoof in the DECTE manifest form the
eligible pool. This pool is deterministically partitioned into:

- **Training set** — 52 speakers.
- **Validation set** — 14 speakers.
- **Test set** — 16 speakers.

The partition uses `numpy.random.default_rng(seed=42).permutation`
over the alphabetically sorted eligible speaker list, so it is
reproducible and independent of downstream code changes. The three
sets are speaker-disjoint by construction, and the file-level
leakage check in `scripts/09_build_mitigation_csvs.py` verifies
this on every run and aborts before writing any output if a speaker
or file appears in more than one set.

### 3.7.2 Training data CSV

For each speaker in the training and validation sets, every valid
bonafide utterance and every successful XTTS spoof for that speaker
is written to an AuralGuard-format training CSV
(`data/decte/metadata/decte_mitigation_train.csv` and
`..._val.csv`). The AuralGuard convention `binary_label = 0` for
bonafide and `binary_label = 1` for spoof is used (this is the
opposite of the "higher score = bonafide" convention on the
detector output side; the two conventions are reconciled at
scoring time). The final training CSV contains 453 bonafide + 258
spoof rows (711 total); the validation CSV contains 129 + 72
(201 total).

### 3.7.3 Held-out test manifest

For the 16 test speakers, a filtered copy of the DECTE spoof
manifest is written to
`data/generated_spoofs/manifest_mitigation_test.jsonl`
(86 successful XTTS rows). Each row also has its `source_audio_path`
resolved and verified — this is what lets the evaluation script
build 86 matched-pair evaluation records (86 bonafide + 86 spoof)
rather than the reference-based 42 bonafide it would build with
only the pre-Entry-5 manifest schema.

### 3.7.4 Fine-tuning configuration

Fine-tuning is done via the AuralGuard project's own `train.py`,
with these choices:

- `--init-checkpoint` points to the baseline `best.pt` (starting
  from the production checkpoint, not from a previous mitigation
  attempt).
- `--freeze-backbone` is set, then followed by `--unfreeze-modules
  "HtrgGAT_layer_ST21,HtrgGAT_layer_ST22,pool_hS2,pool_hT2,master2"`.
  The `--unfreeze-modules` flag was added to `train.py` specifically
  for this thesis (Chapter 6, Section 6.2 documents the patch).
  Only the final heterogeneous-GAT block of the AASIST backbone
  plus the AuralGuard task heads are trainable; every other
  parameter (SincConv front-end, encoder, first-GAT stage) is
  frozen.
- Trainable-parameter count is printed at training start and
  verified: 31,372 trainable of 268,104 frozen (approximately 10.5
  % of the model).
- Hyperparameters: 5 epochs, batch size 4, learning rate 3 × 10⁻⁵,
  `num_workers = 0` (Windows), single GPU.
- Optimiser: AdamW over `filter(lambda p: p.requires_grad,
  model.parameters())` so gradients only flow to the unfrozen
  parameters.
- Best-checkpoint selection: `best.pt` is saved whenever validation
  EER improves on the current best.

### 3.7.5 Guardrails

Two guardrails protect the interpretation of the mitigation result:

- **In-domain sanity check post-training.** The mitigated
  checkpoint is scored on the AuralGuard-original validation set
  (`scripts/06_indomain_sanity_check.py`). Passing this check
  (EER ≤ 5 %) demonstrates that the mitigation did not
  catastrophically forget the original training distribution.
- **VCTK guardrail.** Alongside the DECTE test comparison, the
  same VCTK XTTS manifest used in Chapter 5 is scored under both
  baseline and mitigated checkpoints. If the mitigation had merely
  overfitted to DECTE, the VCTK EER would rise significantly.
  Entry 7's result shows the VCTK delta CI includes zero (no
  statistically significant regression).

### 3.7.6 v1 as motivation for v2

An initial mitigation attempt (v1) fine-tuned only the three task
heads while keeping the entire AASIST backbone frozen (~1,600
trainable parameters). The head-only approach was found to be
insufficient to close the DECTE gap on this test slice, motivating
the modest capacity increase in v2 described above (the last
heterogeneous-GAT block plus the task heads, ~31k trainable
parameters). Both attempts are compared in Chapter 6; the specific
delta EERs and their confidence intervals are reported there.

## 3.8 Subgroup diagnostic protocol

Chapter 7 reports per-subgroup EER before and after mitigation on
the DECTE held-out test slice. This is a descriptive analysis and
is explicitly *not* a fairness audit.

### 3.8.1 Grouping columns

Three headline grouping columns:

- `speaker_gender` (values: `female`, `male`, `mixed`, `unknown`);
- `speaker_age_group` (10-year bands: `16-20`, `21-30`, `31-40`,
  `41-50`, `51-60`, `61-70`, `71-80`, `81-90`; plus `mixed` /
  `unknown`);
- `speaker_recording_era` (DECTE labels such as `1960s-1970s`,
  `1990s`, `2007-2008`, `2008-2009`, `2010-2011`; plus `mixed` /
  `unknown`).

One diagnostic appendix column:

- `speaker_id`. Always low-n given ~5–6 files per test speaker.

The values `unknown`, `mixed`, `fill_in`, `""`, `nan` are skipped
because they represent missing metadata rather than a real subgroup.
`speaker_ses_class` is skipped for DECTE because the extractor emits
`"unknown"` for essentially every speaker.

### 3.8.2 Main-table threshold

A subgroup enters the main table only if it has **at least 10
bonafide and at least 10 spoof files**. Subgroups below this
threshold are shown separately in a low-n diagnostic table (still
computed, but explicitly flagged with `below_n_threshold = True`
in the CSV output). Subgroups with fewer than 5 per class receive
NaN metrics — the metrics themselves are considered undefined at
that sample size.

### 3.8.3 Baseline-vs-mitigated pairing

Baseline and mitigated prediction CSVs are joined on
`(audio_path, label)` with `validate="one_to_one"`. This guarantees
that both detectors were scored on the same file set; if the join
would produce a mismatch, the script errors out rather than silently
computing on unmatched data. Delta EER is then a within-file paired
quantity per subgroup.

### 3.8.4 Wording contract

Because the DECTE held-out slice has only 16 speakers and
per-subgroup n is small, no per-subgroup delta EER is claimed as
statistically distinguishable in this thesis. The chapter's
descriptive-only wording contract is enforced by convention in the
prose (Chapter 7) and by the diagnostic-notes block printed by
`scripts/14_decte_subgroup_diagnostics.py`. In particular:

- **do** say "error concentration in subgroup X", "delta magnitude
  ranked highest in group Y", "worth flagging";
- **do not** say "the detector is biased against X", "unfair to Y",
  or "mitigation helped subgroup X specifically".

## 3.9 Reproducibility notes

Reproducibility was built into the experimental design from the
start, not added on afterwards. The choices below are what let
another researcher re-run any headline number in this thesis from
scratch using the committed code.

### 3.9.1 Environment separation

Three Conda environments, each self-contained:

- **`dialectbias`** — data preparation, metadata extraction,
  detector loading and scoring, LFCC + LR training and scoring,
  bootstrap analyses. Uses PyTorch 2.5 + CUDA 12.1.
- **`spoofgen`** — XTTS v2 spoof generation. Uses Coqui TTS.
- **`openvoice`** — OpenVoice v2 spoof generation. Uses MeloTTS +
  MyShell's OpenVoice library, Python 3.9.

The environments do not share dependencies, and the only shared
artefacts between them are (a) the JSON-Lines manifests under
`data/generated_spoofs*/` and (b) the raw audio under `data/`.

### 3.9.2 Deterministic seeds

The value `42` is used throughout as the base random seed:

- Speaker split for the mitigation partition (`numpy` RNG).
- Target-utterance sampling in `SpoofPipeline.run()`
  (`random.seed(42)`).
- Bootstrap resampling in every CI script (`numpy` default RNG).
- Logistic Regression `random_state` in `scripts/11`.

Where a script performs two independent bootstraps that would
otherwise reuse the same seed (e.g. XTTS vs OpenVoice in Script 5),
the second bootstrap uses `seed + 1` to avoid identical index
sequences.

### 3.9.3 Merge-safe manifests

The manifest writer in `SpoofPipeline._save_manifest` was originally
implemented as a simple "open in write mode and dump `self.results`",
which silently truncated the manifest on any resumed run (because
the resume logic skips already-generated files before adding them to
`self.results`). This was fixed early in the project by loading any
existing manifest first, merging by `output_path`, and rewriting.
Every downstream analysis in the thesis depends on this fix.

### 3.9.4 Repository layout

- `scripts/` — top-level entry points (numbered by execution order:
  01 for data prep, 03 for detector evaluation, 04–13 for statistical
  analyses, 14 for subgroup diagnostics, etc.).
- `configs/` — YAML configs for spoof generation and detector
  evaluation, one config per scale × generator × mitigation-version.
- `src/` — importable modules: `data/`, `spoof_gen/`, `evaluation/`.
- `docs/` — the running findings log and this thesis draft.
- `data/`, `checkpoints/`, `results/` — all gitignored, all
  reproducible from the scripts.

### 3.9.5 Commit-to-entry traceability

Every numbered Entry in `docs/THESIS_FINDINGS_LOG.md` corresponds to
a specific commit on the `main` branch, and every quantitative
claim in Chapters 5–7 traces back to a specific Entry. Appendix A of
the thesis will contain the full commit-hash-to-entry table.

### 3.9.6 External resources required for full reproduction

Four categories of external artefact must be obtained separately
from this repository to reproduce the experiments end-to-end. None
of them are distributed with this thesis, either because of access
restrictions (DECTE) or because of size / licensing considerations
(VCTK, model checkpoints).

- **DECTE corpus access.** DECTE is research-restricted; access
  must be arranged through the corpus custodians \cite{Corrigan_DECTE}.
  The pipeline expects pre-segmented chunk audio under
  `data/01_chunks/` and matched transcripts under
  `data/01_chunk_transcripts/`.
- **VCTK 0.92 download.** Publicly downloadable but not shipped
  with this thesis. See `scripts/00b_verify_vctk_layout.py` for the
  expected on-disk layout under `data/vctk/`.
- **AuralGuard-AASISTPP baseline checkpoint.** The checkpoint used
  as `--init-checkpoint` for every mitigation run and as the primary
  detector's `checkpoint_path` for every evaluation lives in a
  neighbouring `auralguard-aasistpp` repository at
  `results/final_accent_globe_wavefake_balanced_full/best.pt`.
- **Spoof generator checkpoints.** XTTS v2 is downloaded
  automatically by the Coqui TTS library on first use in the
  `spoofgen` environment. OpenVoice v2 requires manually placing the
  tone-colour converter and base-speaker embeddings under
  `checkpoints/openvoice_v2/` (converter checkpoint + config, plus
  `base_speakers/ses/en-us.pth` at minimum).

These four items are the minimum external requirements to reproduce
every number in Chapters 4–7 from scratch.
